# 03_DATA_AND_STATE.md (Данные и Состояние)

## 1. Схема хранения данных (Data Persistence)
Система работает без тяжелых баз данных. Используется максимально простое локальное хранилище.
* **Глобальный Лог Сигналов:** `logs/signals_log.jsonl` (Режим `append-only`). Сюда падают все уникальные сигналы.
* **Black Box (Отчеты по сделкам):** `logs/signals/*.json`. Детальные логи выполнения пайплайна (каждой попытки сделки). Отчет генерируется Снайпером (`trade_executor.ts`), содержит статус (`SUCCESS`, `ABORTED`, `ERROR`), слепок стакана и полную математику расчета (максимальную цену, безопасный объем).

## 2. Управление состоянием (State Management)
Глобальное состояние живет в оперативной памяти (RAM) процесса Node.js.

### 2.1. Состояние CDP-подключения
* Хранит ссылку на активную сессию браузера (`CDP Session`).
* Статусы: `DISCONNECTED`, `CONNECTED`. На этапе Итерации 1 при обрыве связи скрипт завершает процесс (Fail-Fast).

### 2.2. Фильтрация и Кэш в Сканере (Scanner Logs)
* **Анти-спам кэш:** In-memory `Map<string, number>` живущий в модуле сканера.
  * Если тикер есть в кэше, он отбрасывается в течение 60 секунд (`ANTI_SPAM_TTL_MS`).
* **Динамический Blacklist:** In-memory массив `string[]`, подгружаемый из `blacklist.txt`.
  * Использует `fs.watchFile` для обновления массива **на лету** без перезапуска бота. Скам-монеты из списка отбрасываются мгновенно.
* **Проверка Спреда:** Проверяет `MIN_ARB_PERCENT`. Если профит в сигнале ниже конфигурационного, сигнал гасится на самом раннем этапе.

### 2.3. Живой стакан биржи (XT Orderbook)
* **Проблема:** Нехватка ликвидности при покупке актива "по рынку" может привести к заморозке депозита из-за большого проскальзывания.
* **Хранилище:** In-memory `Map<string, number>` для уровня цен и их объемов в модуле `src/features/xt_orderbook.ts`.
* **Логика:** Раздельные словари для `Asks` (Продавцы) и `Bids` (Покупатели). Позволяет мгновенно обновлять `O(1)` или удалять цены при получении WebSocket-дельт без перестроения массивов. Обновляется синхронно с биржей, используется для симуляции проскальзывания.

## 3. Контракты данных (TypeScript DTOs)
Строгая типизация входящего сигнала из WebSocket-трафика. 

```typescript
// src/shared/types.ts

export interface IExchangeData {
  exchange: string;           // Биржа (например 'MEXC', 'xt', 'JUP')
  avg_price?: number;         // Средняя цена
  min_price?: number;         // Минимальная цена
  max_price?: number;         // Максимальная цена
}

export interface ISignalPayload {
  symbol: string;             // Тикер (например, "RNGR")
  arb_percent: number;        // Процент арбитража (например, 0.63)
  arbitrage_amount_usdt: number; // Объем в USDT
  
  small: IExchangeData;       // Биржа покупки (CEX, отстающая)
  big: IExchangeData;         // Биржа продажи (DEX, ценообразующая)
  
  buy_url?: string;           // Готовая ссылка (опционально)
  sell_url?: string;          // Готовая ссылка (опционально)
}

export interface IOpenTabsPayload {
  urls: string[];             // Массив URL для открытия в браузере (после трансформации)
}
```

## 4. Правила доступа к данным
Модуль фильтрации (в слое features/) сначала проверяет наличие тикера в In-memory кэше, и только если его там нет — публикует событие на открытие вкладок через Event Bus.
