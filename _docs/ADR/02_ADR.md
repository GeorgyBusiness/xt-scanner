# ADR-002: Парсинг, Типизация и Авто-реконнект сканера

**Дата создания:** 2026-03-08
**Статус:** `Completed`
**Связанные Epic/Task:** Этап 2 (ROADMAP.md)

---

## 1. Контекст и Бизнес-задача (Context)
* Для перехода ко второму этапу Roadmap необходимо научить систему распознавать целевые сигналы в сыром WebSocket-трафике, отсеивать мусор (телеметрию) и извлекать данные о связке CEX -> DEX.
* Система должна быть устойчивой: обрыв CDP-сессии (например, при обновлении страницы сканера пользователем) не должен приводить к падению Node.js процесса (ранее использовался `process.exit(1)`). Требуется механизм автоматического переподключения (Auto-reconnect).
* Для удобства тестирования нужно иметь возможность отключать жесткую фильтрацию по целевой бирже (XT) и видеть все сигналы (например, MEXC, Gateio), а также выводить сырые данные (Raw JSON) при необходимости.

## 2. Предлагаемое решение (Proposed Solution)
* **Архитектура парсера:** В слое фичей создается модуль `scanner.ts`, который экспортирует чистую функцию парсинга. На вход подается строка (фрейм), на выходе — массив типизированных сигналов `ISignalPayload[]` или пустой массив (если это мусор).
* **Валидация данных:** Используется "утиная типизация" (`try/catch` + TypeScript интерфейсы). Жесткая runtime-валидация через сторонние библиотеки (типа Zod) отклонена для обеспечения Graceful Degradation (снижения хрупкости системы).
* **Фильтрация и Флаги:** * Отказ от фильтрации по DEX (сигналы всегда идут на целевые DEX).
  * Ввод флага `CEX_FILTER_ENABLED` в `config.ts`. Если `false`, парсер пропускает и форматирует любые найденные CEX-биржи. Если `true`, ищет только `TARGET_CEX` (например, `xt`).
  * Ввод флага `DEBUG_RAW_SIGNALS` в `config.ts` для вывода нераспарсенного JSON на случай изменения API сервером.
* **Авто-реконнект:** В `main.ts` внедряется цикл `while(true)` с блоком `try/catch`. При потере связи `cdp_client.ts` бросает ошибку `Error` вместо завершения процесса. `main.ts` ловит её, ждет 3 секунды (Sleep) и инициирует новое подключение, аккуратно очищая старые слушатели во избежание утечек памяти.

## 3. Изменения в Данных и Состоянии (Data & State)
* **State:** Добавляется In-memory обработка массива сигналов внутри фрейма (сервер присылает `payloadData` как JSON-строку, содержащую массив объектов).
* **Контракты (DTOs):** Описывается интерфейс `ISignalPayload` в `src/shared/types.ts`. На основе реальных логов выделены ключевые поля:
  * `symbol` (например, "RNGR")
  * `arb_percent` (например, 0.63)
  * `arbitrage_amount_usdt` (объем в USDT)
  * `small.exchange` (биржа покупки, CEX)
  * `big.exchange` (биржа продажи, DEX)
  * `buy_url` и `sell_url` (готовые ссылки для Итерации 4).

## 4. Интеграции и AI (Integrations)
* Добавленный флаг `DEBUG_RAW_SIGNALS` работает как механизм "AI-First Observable": при ошибках парсинга разработчик мгновенно получает сырой дамп, который можно скормить LLM для быстрой генерации фикса структуры интерфейсов.

* `src/shared/types.ts` — Создать файл и описать интерфейсы `ISignalPayload`, `IExchangeData` и т.д.

* `src/main.ts` — Изменить: обернуть логику в `while(true)`, добавить `try/catch` с задержкой, подключить вызов сканера и форматированный вывод в `console.log`.

## 6. Пошаговый план реализации (Execution Steps)
1. Обновить глобальный `config.ts`, добавив новые параметры фильтрации и дебага.
2. Создать `src/shared/types.ts` и перенести туда структуру на основе реального JSON.
3. Создать `src/features/scanner.ts`. Написать логику: `JSON.parse` -> проверка на массив -> фильтрация телеметрии -> проверка `small.exchange` (с учетом `CEX_FILTER_ENABLED`) -> возврат массива сигналов.
4. Отрефакторить `src/core/cdp_client.ts` для поддержки Graceful Error Handling.
5. Отрефакторить `src/main.ts`: добавить цикл реконнекта, передавать `payloadData` в функцию сканера и красиво выводить результат (например, `[🔥 СИГНАЛ] RNGR | MEXC -> JUP | Профит: 0.63% ($4.19)`).
