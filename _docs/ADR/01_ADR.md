# ADR-001: Фундамент интеграции с браузером и перехват трафика (CDP Connection)

**Дата создания:** 2026-03-08
**Статус:** `Approved`
**Связанные Epic/Task:** Этап 1 (ROADMAP.md)

---

## 1. Контекст и Бизнес-задача (Context)
* Для реализации системы "XT Scanner" необходимо научиться подключаться к запущенному экземпляру Google Chrome и пассивно перехватывать сырой сетевой трафик (WebSocket) без вмешательства в работу страниц.
* **Проблема выбора:** Выбор между `puppeteer-core` и `chrome-remote-interface`.
* **Решение:** Проведенный ресерч показал, что `puppeteer-core` имеет жесткую привязку к версиям браузера и избыточен для задач без DOM-манипуляций. Выбрана библиотека `chrome-remote-interface` для обеспечения максимальной совместимости (Forward Compatibility) с будущими версиями Chrome.

## 2. Предлагаемое решение (Proposed Solution)
* Инициализация базового Node.js + TypeScript проекта.
* Использование `chrome-remote-interface` для подключения к Chrome по CDP (Chrome DevTools Protocol).
* Создание глобального конфигурационного файла `config.ts`, в который сразу закладываем параметры для будущих этапов (включая флаг `OPEN_TABS_IN_BACKGROUND`).
* Создание базового модуля `cdp_client.ts` в слое общих инструментов (Core) для инкапсуляции логики подключения.
* На данном этапе (Итерация 1) авто-переподключение (Exponential Backoff) не реализуется. При обрыве связи скрипт должен выводить ошибку в консоль и завершать процесс (Fail-Fast).
* Входная точка `main.ts` должна устанавливать соединение, включать домен `Network` и логировать сырые события `Network.webSocketFrameReceived` прямо в терминал.

## 3. Изменения в Данных и Состоянии (Data & State)
* **БД:** База данных не используется.
* **State:** Состояние подключения (активно/разорвано) хранится в оперативной памяти внутри `cdp_client.ts`.

## 4. Интеграции и AI (Integrations)
* Подключение осуществляется локально (127.0.0.1) на кастомный порт отладки (по умолчанию `48192`). 
* Пользователь должен запускать Chrome со специальным флагом (например, `--remote-debugging-port=48192`).

## 5. Затронутые файлы (Affected Files)
* `package.json` — Инициализация проекта, добавление зависимостей (`chrome-remote-interface`, `typescript`, `@types/node`).
* `tsconfig.json` — Настройка строгой типизации TypeScript.
* `config.ts` — Создание глобального файла конфигурации.
* `src/core/cdp_client.ts` — Создание клиента для управления CDP-сессией.
* `src/main.ts` — Создание точки входа и логики вывода трафика в консоль.

## 6. Пошаговый план реализации (Execution Steps)
1. Инициализировать проект: создать `package.json` и `tsconfig.json` с настройками под Node.js (ESM или CommonJS, в зависимости от предпочтений, рекомендуется строгий режим). Установить `chrome-remote-interface`.
2. Создать файл `config.ts` в корне проекта со следующей структурой:
   - `CDP_PORT`: 48192
   - `CDP_HOST`: '127.0.0.1'
   - `OPEN_TABS_IN_BACKGROUND`: false (задел на будущее)
3. Создать `src/core/cdp_client.ts`. Реализовать класс или функцию для коннекта через `chrome-remote-interface`. При обрыве соединения вызывать `process.exit(1)` с понятным сообщением об ошибке.
4. Создать `src/main.ts`. Вызвать подключение из `cdp_client`, отправить команду `Network.enable()` и подписаться на событие `Network.webSocketFrameReceived`. Все входящие параметры события выводить через `console.log`.
