# ADR-006: CDP-Снайпер (Execution) и Математика выкупа (Sweep)

**Дата создания:** 2026-03-09
**Статус:** `Draft`
**Связанные Epic/Task:** ROADMAP v2.0 (Фаза 1: Шаг 2 и Шаг 3)

---

## 1. Контекст и Бизнес-задача (Context)
* В рамках перехода к полной автоматизации (Full Auto) необходимо реализовать модуль исполнения сделок (Execution) на бирже XT.com.
* **Проблема 1 (Anti-Bot):** Обычный JS-клик `button.click()` блокируется защитой биржи (`isTrusted = false`).
* **Проблема 2 (Динамическая верстка):** Сайт XT.com использует React с хэшированными CSS-классами (например, `class="number_main__Ym0oL"`). Привязка к классам приведет к поломке бота при первом же обновлении сайта.
* **Проблема 3 (Математика):** Выставление лимитки "вслепую" ведет к зависанию неисполненного объема в стакане. Необходимо "пылесосить" (Sweep) стакан XT строго до цены Reference DEX (Jupiter) в рамках выделенного лимита (например, 300 USDT).

## 2. Предлагаемое решение (Proposed Solution)
* **Архитектура (Feature-First):** Создается новый изолированный модуль `src/features/xt_sniper.ts`, который выступает "руками" системы. Оркестратор (`main.ts`) принимает решение, а Снайпер только исполняет клики.
* **Математика Свипа:** В модуль `xt_orderbook.ts` добавляется метод `calculateSweep(maxPrice: number, budgetUsdt: number)`. Он считает, сколько объема доступно до цены Юпитера. Если доступно меньше бюджета, Снайпер покупает только на доступный объем. Это исключает зависание лимиток.
* **Поиск элементов (XPath):** Для обхода динамических классов Снайпер использует CDP-команду `Runtime.evaluate` с поиском через XPath по статичным текстовым лейблам (например, `//div[text()='Price']/following-sibling::input` и `//button[contains(., 'Buy')]`).
* **Эмуляция человека:** Снайпер использует команды C++ движка браузера: `Input.dispatchMouseEvent` и `Input.insertText` с микрозадержками (50-80 мс), гарантируя получение флага `isTrusted = true`.
* **Изолированное тестирование:** Создается файл `src/test_sniper.ts`, который проверяет только механику ввода цифр и наведения мыши (без отправки реального ордера).

## 3. Изменения в Данных и Состоянии (Data & State)
* **БД:** Нет изменений.
* **State:** В `config.ts` добавляется новый глобальный параметр: `FIXED_BUY_USDT` (например, 300) — жесткий лимит бюджета на одну сделку.

## 4. Интеграции и AI (Integrations)
* Взаимодействие происходит исключительно через CDP домены `Runtime` (для поиска координат элементов через DOM) и `Input` (для отправки хардверных событий ввода).

## 5. Затронутые файлы (Affected Files)
* `config.ts` — Добавить параметр `FIXED_BUY_USDT: number`.
* `src/features/xt_orderbook.ts` — Добавить метод математики свипа `calculateSweep`.
* `src/features/xt_sniper.ts` — Создать новый модуль для инъекции кликов и ввода текста через CDP.
* `src/test_sniper.ts` — Создать CLI-скрипт для визуального тестирования ввода данных Снайпером.
* `package.json` — Добавить скрипт `"test:sniper": "ts-node src/test_sniper.ts"`.

## 6. Пошаговый план реализации (Execution Steps)
1. **Config & Math:**
   * Добавить `FIXED_BUY_USDT = 300` в `config.ts`.
   * В `XTOrderbookManager` написать метод `calculateSweep(maxPriceLimit, targetUsdt)`. Он должен вернуть `{ safePrice, safeAmountUsdt }`. `safePrice` — это цена самой дорогой заявки, которую мы забираем. `safeAmountUsdt` — это сумма в $, на которую мы реально можем купить до достижения лимита цены.
2. **Снайпер (xt_sniper.ts):**
   * Создать класс `XTSniper`, принимающий `CDP.Client`.
   * Написать метод поиска координат элемента через XPath: передаем `//div[text()='Price']/following-sibling::input` в `Runtime.evaluate`, получаем `getBoundingClientRect()`, вычисляем центр `(x, y)`.
   * Написать методы `clickAt(x, y)` и `typeText(text)` используя `Input.dispatchMouseEvent` (с задержкой 50мс между `mousePressed` и `mouseReleased`) и `Input.insertText`.
3. **Бизнес-процесс Снайпера:**
   * Метод `executeBuy(price: string, amountUsdt: string)`:
     1) Кликает в инпут цены, стирает старое (Backspaces), вписывает `price`.
     2) Кликает в инпут суммы, стирает старое, вписывает `amountUsdt`.
     3) Находит кнопку Buy PUNCH, наводит курсор, но **клик временно закомментирован** для безопасности тестов.
4. **Тест (test_sniper.ts):**
   * Подключается к XT.com (к открытой монете).
   * Вызывает `sniper.executeBuy("0.0105", "150.50")`.
   * Разработчик должен визуально увидеть, как в браузере сами вбиваются цифры.
