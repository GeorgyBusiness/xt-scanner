# ADR-005: Интеграция живого стакана XT (In-Memory Orderbook) и расчет проскальзывания

**Дата создания:** 2026-03-09
**Статус:** `Draft`
**Связанные Epic/Task:** ROADMAP v2.0 (Фаза 1: Шаг 1 и Шаг 2)

---

## 1. Контекст и Бизнес-задача (Context)
* В рамках перехода к полностью автономному торговому боту (Full Auto) необходимо решить проблему проскальзывания (Slippage) и риска появления "зависших лимитных ордеров" на покупку.
* Покупка "вслепую" по данным только из сигнала опасна, так как в стакане может не оказаться достаточного объема (Volume) по нужной цене, что приведет к частичному исполнению заявки и заморозке депозита.
* **Бизнес-задача:** Научить бота "видеть" живой стакан биржи XT.com в оперативной памяти и математически рассчитывать среднюю цену покупки заданного объема (USDT) перед тем, как отдать команду на физический клик мышью.

## 2. Предлагаемое решение (Proposed Solution)
* Согласно правилу слабой связанности (Feature-First), создается новый независимый модуль `src/features/xt_orderbook.ts`.
* **Перехват (Observation):** Модуль использует текущий CDP-клиент (домен `Network`) для перехвата данных без прямого подключения к API биржи:
  1. Слушает `Network.responseReceived`. Находит HTTP Fetch-запрос, содержащий в URL слово `depth` (стартовый слепок стакана), и через `Network.getResponseBody` извлекает 100 уровней стакана.
  2. Параллельно слушает `Network.webSocketFrameReceived`. Находит фреймы `topic: "depth_update"` (Дельты).
* **Синхронизация:** Модуль сохраняет Дельты в буфер до получения Слепка. После получения Слепка, Дельты применяются к нему с проверкой `lastUpdateId` (из HTTP) и `i` / `fi` (из WS) для исключения рассинхрона.
* **Изолированное тестирование:** Создается файл `src/test_orderbook.ts`, который подключается к XT.com по указанной ссылке и выводит живой стакан прямо в консоль терминала с помощью перезаписи экрана (Live Dashboard). БЕЗ подключения к общей шине сигналов.
* **Математика:** Модуль экспортирует метод `calculateAveragePrice(targetUsdt: number)`, который проходит циклом по In-Memory стакану `Asks` и возвращает либо среднюю цену покупки заданного объема, либо ошибку `null` (если объема в стакане не хватает).

## 3. Изменения в Данных и Состоянии (Data & State)
* **БД:** Изменений нет.
* **State:** Появление локального In-memory состояния внутри класса `XTOrderbook`. 
  * Используется структура `Map<string, number>` (Цена -> Объем) для мгновенного доступа и обновления ключей (цен).
  * Массивы `Asks` (Продавцы) и `Bids` (Покупатели) хранятся в ОЗУ раздельно.

## 4. Интеграции и AI (Integrations)
* Добавляется перехват HTTP-ответов (`Network.responseReceived`, `Network.getResponseBody`) через библиотеку `chrome-remote-interface`.
* Взаимодействие с UI биржи в режиме "Read-Only". Инъекция JS-кода или REST-запросы от лица Node.js запрещены во избежание банов.

## 5. Затронутые файлы (Affected Files)
* `src/shared/types.ts` — Создать интерфейсы для JSON-структур стакана (HTTP Snapshot и WS Deltas).
* `src/features/xt_orderbook.ts` — Создать новый модуль логики перехвата, склейки стакана и математики проскальзывания.
* `src/test_orderbook.ts` — Создать скрипт (CLI Симулятор-Дашборд) для изолированного визуального тестирования.
* `package.json` — Добавить NPM скрипт `"test:orderbook": "ts-node src/test_orderbook.ts"`.

## 6. Пошаговый план реализации (Execution Steps)
1. Открыть `src/shared/types.ts`. Добавить интерфейсы `IXTSnapshotResponse` (с полями `lastUpdateId`, `bids`, `asks` в виде строк-массивов) и `IXTDeltaFrame` (с полями `i`, `fi`, `a`, `b`).
2. Создать `src/features/xt_orderbook.ts`. Реализовать класс `XTOrderbookManager`:
   * Инициализировать пустые `Map` для bids и asks.
   * Настроить подписки на события CDP `Network`.
   * Реализовать логику буферизации дельт и применения их к слепку (сравнение `lastUpdateId` с полем `i`).
   * Реализовать удаление цены из `Map`, если пришла дельта с объемом `"0.00"`.
3. В этом же классе `xt_orderbook.ts` написать метод `calculateExecution(targetUsdt: number)`:
   * Сортировать ключи `Asks` по возрастанию (от дешевых к дорогим).
   * Идти по уровням, умножая цену на объем, пока накопительная сумма не достигнет `targetUsdt`. 
   * Вернуть объект `{ averagePrice, maxPriceHit, isVolumeSufficient }`.
4. Создать `src/test_orderbook.ts`. 
   * Инициировать подключение CDP.
   * Открыть любую вкладку XT Spot через `Target.createTarget`.
   * Инстанцировать `XTOrderbookManager`.
   * Использовать `setInterval` (например, 100 мс) и `console.clear()`, чтобы красиво печатать в терминале топ-10 `Asks` и топ-10 `Bids`, эмулируя торговый терминал для визуального контроля правильности математики.
5. Обновить `package.json`, добавив команду запуска `test:orderbook`.
