# 04_INTEGRATIONS.md (Внешние сервисы и Сеть)

## 1. Интеграция с локальным браузером (CDP)
Главная интеграция системы — подключение к уже запущенному экземпляру Google Chrome на компьютере пользователя.
* **Протокол:** Chrome DevTools Protocol (CDP).
* **Библиотека:** `chrome-remote-interface` (Node.js).
* **Сетевая инфраструктура:** Подключение происходит исключительно через `localhost` (127.0.0.1) на кастомный порт отладки (например, `48192`), отличный от стандартного 9222.
* **Жизненный цикл и Target Discovery:** Скрипт активно ищет нужную вкладку (сканер) среди всех открытых вкладок по фрагменту URL (`SCANNER_URL_MATCH`). 
* **Устойчивость (Auto-Reconnect):** В случае случайного закрытия целевой вкладки, обновления страницы пользователем или падения браузера, скрипт не завершает работу (Fail-Fast заменен на Auto-reconnect). Он ловит ошибку дисконнекта, переходит в режим ожидания (Sleep) и бесконечно пытается заново подключиться к CDP, пока сессия не восстановится.
* **Focus Window & Memory Saver:** Функция "Режим энергосбережения" и "Экономия памяти" в Chrome усыпляют фоновые неактивные вкладки. Чтобы обойти эту проблему и гарантировать рендеринг DOM (появление кнопки Buy), бот использует CDP-команду `tabClient.Page.bringToFront()` перед началом работы со стаканом. Это переключает фокус вкладки принудительно.
* **Изолированный профиль (Инструкция по запуску):** Для работы сканера используется специальный флаг ` --user-data-dir="/tmp/chrome_dev_test"`. Это создает изолированную сессию (macOS), которая не конфликтует с обычными окнами пользователя и гарантированно корректно открывает порт отладки без сбоев.

## 2. API-провайдеры (Биржи)
В рамках Итерации 1 скрипт **НЕ использует** REST/WebSocket API бирж (XT.com, Jupiter). 
* **Как работает:** Взаимодействие с биржами происходит путем открытия страниц через `Target.createTarget` и последующего автоматического исполнения (Снайпер). Вкладки открываются активно (в фокусе), так как потеря фокуса текущей страницей сканера (`has_focus: false`) является штатным поведением.
* **Автоматизация исполнения:** Модуль Снайпера (Execution) использует домены CDP `Input` (отправка аппаратных событий мыши и клавиатуры с микрозадержками, что гарантирует флаг `isTrusted = true` и обход Anti-Bot систем) и `Runtime` (вычисление координат элементов через XPath-селекторы прямо в браузере для обхода динамических React-хэшей сайта XT.com).

## 3. Системные ресурсы (macOS)
* **Аудио Уведомления:** Встроенная утилита macOS `afplay` вызывается через `child_process.exec()` из модуля `trade_executor.ts`. Подхватывает рандомный `.mp3` файл из папки `Sounds/` при успешном прохождении боевой сделки (когда `DRY_RUN: false`).

## 4. Сетевая инфраструктура и Антифрод
* Скрипт является полностью пассивным слушателем (Read-Only) на сетевом слое (Network Domain CDP).
* Телеметрия стороннего сканера (`ui_telemetry_batch`) уходит на сервер провайдера в штатном режиме. Открытие новых вкладок является легитимным поведением пользователя.
* **Билингвальность Снайпера:** Снайпер использует обобщенные XPath-запросы ("Buy" или "Купить", "Price" или "Цена") для поиска DOM-элементов биржи без привязки к локали аккаунта XT.com.
