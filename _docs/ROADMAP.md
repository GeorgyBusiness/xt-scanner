# ROADMAP.md (План пошаговой реализации)

## Введение
Разработка модуля **XT Scanner** ведется итеративно (по принципу Milestones). Это необходимо для пошагового тестирования нестандартной интеграции с Chrome DevTools Protocol (CDP) и предотвращения галлюцинаций ИИ-кодера при написании большого объема кода. Каждая итерация должна быть полностью протестирована вручную перед переходом к следующей.

---

## 🟢 Этап 1: Фундамент и «Прослушка» (CDP Connection)
**Цель:** Научиться подключаться к живому браузеру Chrome и перехватывать сырой сетевой трафик без вмешательства в работу страниц.
**STATUS:** PLANNED

* **Задачи для ИИ:**
  1. Инициализация Node.js проекта (`package.json`, `tsconfig.json`).
  2. Создание `config.ts` с настройками (порт отладки `48192`).
  3. Создать модуля `src/core/cdp_client.ts` для подключения к браузеру (через `puppeteer-core` или `chrome-remote-interface`).
  3.5. **Микро-шаг 1.5:** Внедрение Target Discovery — запрос `CDP.List` и поиск целевой вкладки по `config.SCANNER_URL_MATCH` перед передачей `target` в рабочую сессию.
  4. Создание базового `src/main.ts`, который устанавливает соединение, включает `Network.enable` и выводит в консоль все входящие события `Network.webSocketFrameReceived`.
* **Критерии приемки (Как тестируем):**
  1. Запускаем Chrome: /Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=48192 --user-data-dir="/tmp/chrome_dev_test"
  2. Запускаем скрипт.
  3. Открываем любой сайт с веб-сокетами (или оригинальный сканер) и убеждаемся, что в консоль терминала падают сырые сетевые пакеты.

## 🟡 Этап 2: Парсинг и Типизация (Scanner Feature)
**Цель:** Отфильтровать мусорный трафик, вычленить целевые арбитражные сигналы (XT -> DEX) и строго их типизировать.
**STATUS:** PLANNED

* **Задачи для ИИ:**
  1. Описать интерфейс входящего сигнала `ISignalPayload` в `src/shared/types.ts`.
  2. Создать модуль `src/features/scanner.ts`.
  3. Реализовать в модуле логику парсинга JSON из фреймов, игнорирование системной телеметрии (например, `ui_telemetry_batch`) и фильтрацию по биржам (ищем `xt` в CEX и `jup`/`raydium` в DEX).
  4. Обновить `main.ts` для использования сканера.
  5. **Непрерывность работы:** Реализовать цикл `while(true)` в `main.ts` с ожиданием (например, 3 секунды) для бесконечных попыток автоматического переподключения (Авто-реконнект), если сессия была разорвана (например, вкладка обновлена или закрыта). Отказаться от `process.exit(1)`.
* **Критерии приемки (Как тестируем):**
  1. Запускаем скрипт и оригинальный сканер.
  2. При поступлении реального сигнала в консоли должен появиться аккуратно распарсенный JSON (или лог с тикером и профитом), а мусорный трафик должен молча игнорироваться.

## 🟠 Этап 3: Шина Событий и Логирование (Event Bus & Logger)
**Цель:** Внедрить событийно-ориентированную архитектуру для слабой связанности фич и научиться сохранять историю сигналов.
**STATUS:** PLANNED

* **Задачи для ИИ:**
  1. Создать легковесную шину событий `src/core/event_bus.ts` (Publisher/Subscriber).
  2. Изменить `scanner.ts`: теперь при нахождении сигнала он не принтует его в консоль, а публикует `SignalDetectedEvent` в Event Bus.
  3. Создать модуль `src/features/logger.ts`, который подписывается на событие и дописывает (append) данные сигнала в локальный файл `logs/signals_log.jsonl`.
* **Критерии приемки (Как тестируем):**
  1. Получаем сигнал.
  2. Проверяем, что в корне проекта появилась папка `logs/` и файл `signals_log.jsonl`, и в него корректно записалась новая строка с валидным JSON.

## 🔴 Этап 4: Анти-спам и Открытие вкладок (Tab Manager & Cache)
**Цель:** Реализовать финальное целевое действие (открытие ссылок XT и Jupiter) с защитой браузера от зависания при дублирующихся сигналах.
**STATUS:** PLANNED

* **Задачи для ИИ:**
  1. Добавить в `src/features/scanner.ts` In-memory кэш (`Set<string>`) для хранения тикеров (например, `PYBOBO`) с логикой TTL (удаление через 60 секунд). Повторные сигналы игнорируются.
  2. Создать модуль `src/features/browser_tabs.ts`.
  3. Подписать этот модуль на `SignalDetectedEvent`. При срабатывании модуль должен формировать целевые URL и отправлять CDP-команду `Target.createTarget` для мгновенного открытия двух новых вкладок.
* **Критерии приемки (Как тестируем):**
  1. Ждем реальный сигнал.
  2. Проверяем, что в рабочем браузере мгновенно и без фокуса открылись две новые целевые вкладки.
  3. При поступлении дубля этого же сигнала через пару секунд новые вкладки **не** открываются.
