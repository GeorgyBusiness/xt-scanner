# 01_BUSINESS_DOMAIN.md (Смыслы и Правила)

## 1. Суть продукта
**XT Scanner** — это локальная автоматизированная система для эксплуатации арбитражных возможностей (latency arbitrage) в направлении XT.com -> DEX (покупка на отстающей CEX XT.com и продажа на ценообразующей DEX, такой как Jupiter). Система работает не как самостоятельный сканер, а как скрытый наблюдатель, пассивно подключаясь к сетевому трафику стороннего веб-сканера сигналов в браузере пользователя.

## 2. Бизнес-логика и Механика
* **Источник данных:** WebSocket-трафик оригинального веб-сканера. Перехват осуществляется через Chrome DevTools Protocol (CDP).
* **Триггер:** Поступление JSON-сообщения, содержащего связку XT.com -> DEX. Сигнал отлавливается на уровне сетевого слоя браузера.
* **Целевое действие:** Мгновенное автоматическое открытие двух вкладок:
  1. График монеты на Jupiter (секундный таймфрейм).
  2. Страница торгов монетой на XT.com для ручного совершения сделки.
* **Анти-спам фильтр:** Защита системы от сотен дублирующихся сигналов через In-memory TTL кэш (настраивается как `ANTI_SPAM_TTL_MS`). Повторные сигналы одного тикера молча отбрасываются в течение заданного времени, предотвращая спам в логах и Event Bus.
* **Черный список (Blacklist):** Мгновенная фильтрация нежелательных токенов (например, Scam-монет) через подгружаемый и динамически обновляемый файл `blacklist.txt`.
* **Логирование и Обратная связь:**
  * Сохранение всех входящих уникальных сигналов в файл `logs/signals_log.jsonl`.
  * Детальный отчёт (Black Box) по каждой попытке входа в сделку сохраняется в `logs/signals/`.
  * При успешном выполнении боевой сделки (не DRY_RUN) проигрывается звуковой файл из папки `Sounds/`.
* **Правила безопасности (Anti-Ban):**
  * **Строгий Read-Only режим:** Абсолютно ЗАПРЕЩАЕТСЯ вмешиваться в DOM-дерево страницы стороннего сканера, использовать команды `Runtime.evaluate` для инъекции JS-кода или изменять глобальные переменные.
  * Запрещается создавать параллельные WebSocket подключения к серверу сканера.
  * CDP-подключение должно производиться на нестандартный порт (отличный от дефолтного 9222).

## 3. Защита от проскальзывания (Slippage Protection)
* **Проблема:** Покупка "вслепую" по данным только из сигнала может привести к частичному исполнению заявки и заморозке депозита, если в стакане (Orderbook) биржи не окажется достаточного объема `Volume` по нужной цене.
* **Решение (Sweep стакана):** Добавлена механика In-Memory Orderbook — бот в реальном времени поддерживает слепок стакана и математически рассчитывает доступный объем (свип/пылесос стакана) до допустимой цены Reference DEX в рамках выделенного лимита `FIXED_BUY_USDT`. Если объем недостаточен для полного бюджета, бот купит лишь на ту сумму, которая гарантированно исполнится мгновенно, полностью исключая зависание лимиток в стакане.

## 3. Сущности
* **Target CEX:** Целевая биржа для покупки на отставании (XT.com).
* **Reference DEX:** Ценообразующая биржа, куда планируется вывод (Jupiter, Raydium).
* **CDP Listener:** Локальный скрипт-перехватчик трафика, слушающий порт отладки браузера.

## 4. Формирование URL
* **XT.com:** `https://www.xt.com/en/trade/{symbol}_usdt`
* **Jupiter:** Изначальный сигнал содержит Swap-ссылки вида `https://jup.ag/swap?sell={ADDRESS}`. Для быстрого принятия решения пользователем система на лету трансформирует их в страницу токена: `https://jup.ag/tokens/{ADDRESS}`.

## 5. Флаги конфигурации и Отладка (Config & Debug)
* **`CEX_FILTER_ENABLED`**: Позволяет включать/отключать жесткую фильтрацию по целевой бирже (например, XT.com). Если `false`, система обрабатывает сигналы со всех доступных CEX, что полезно для тестирования и анализа охвата.
* **`DEBUG_RAW_SIGNALS`**: Механизм "AI-First Observable". При ошибках парсинга выводит в консоль сырой (raw) нераспарсенный JSON-фрейм. Это позволяет скопировать лог и моментально передать ИИ-ассистенту для генерации исправленного интерфейса TypeScript, не прибегая к запуску отладчика.
* **`MIN_ARB_PERCENT`**: Минимально необходимый процент профита для обработки сигнала. Если профит ниже (например, 2.0%) — сигнал молча игнорируется.
* **`DRY_RUN`**: Режим холостого хода. Позволяет системе прогнать весь пайплайн (Сбор стакана, фокус вкладки, ввод цены/количества), но отменить финальный клик по кнопке "Buy".
