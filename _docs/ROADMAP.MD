# 🗺️ ROADMAP v2.0: Full Auto Concept (XT -> Jupiter)

Данный документ описывает поэтапный план перехода от ручного исполнения сигналов к полностью автономному торговому боту (Full Auto) через CDP-инъекции.

## 🏁 Фаза 1: Авто-Покупка на CEX (XT.com)
**Цель:** Научить бота самостоятельно и безопасно выкупать актив на отстающей бирже XT.com по нужной цене, информируя пользователя о необходимости ручной продажи на DEX.

* [ ] **Шаг 1: Подключение к стакану XT (Observation).**
  * Исследование: Перехват внутреннего WebSocket-трафика XT.com через CDP (домен Network) для чтения стакана (Orderbook).
  * Реализация: Парсинг JSON-стакана в In-memory хранилище для постоянного доступа к актуальной цене `Ask`.
* [ ] **Шаг 2: Модуль расчета проскальзывания (Slippage Math).**
  * Реализация: Использование `simulator.ts` для прогона исторических сигналов. Написание логики проверки объемов: "Достаточно ли ликвидности в стакане по текущей цене Ask, чтобы купить на X USDT?".
* [ ] **Шаг 3: CDP-Снайпер CEX (Execution).**
  * Реализация: Открытие отдельного окна биржи фиксированного размера (для стабильности верстки).
  * Реализация: Использование `Input.dispatchMouseEvent` и `Input.insertText` (на уровне движка C++) для ввода суммы покупки и безопасного клика по кнопке "Buy" с имитацией человеческой задержки (isTrusted = true).
* [ ] **Шаг 4: Система алертов (OS Notifications).**
  * Реализация: Интеграция звуковых оповещений (Audio) или OS Push-уведомлений при успешном срабатывании ордера на покупку. (Триггер для ручной продажи).

## 🚀 Фаза 2: Авто-Продажа на DEX (Jupiter)
**Цель:** Полное замыкание арбитражного цикла. Автоматическая продажа купленного актива на ценообразующей DEX без участия человека.

* [ ] **Шаг 5: Чтение котировок DEX (Jupiter Quote Observation).**
  * Исследование: В отличие от CEX, на Jupiter выгоднее использовать их открытое публичное API (Jupiter v6 API), так как DEX не банят за ботов. Альтернатива: чтение UI через CDP.
  * Реализация: Скрипт запрашивает актуальный Quote (маршрут обмена) для нашего токена и убеждается, что арбитражный спред все еще плюсовой.
* [ ] **Шаг 6: Подготовка среды и кошелька.**
  * Настройка: Предварительная авторизация Web3-кошелька (Phantom/Solflare) в изолированном профиле Chrome (`chrome_dev_test`). Включение функции "Auto-Approve" в кошельке (если доступно) для обхода всплывающих окон.
* [ ] **Шаг 7: CDP-Снайпер DEX (Execution).**
  * Реализация: Если Auto-Approve недоступен, настройка CDP для перехвата фокуса на всплывающее окно Phantom и автоматического клика "Подтвердить" (Approve) через `Input.dispatchMouseEvent`.
* [ ] **Шаг 8: PnL Логгер и Замыкание цикла.**
  * Реализация: Расширение `logger.ts`. Запись результатов обеих ног сделки (Buy на XT, Sell на Jup) и расчет итоговой чистой прибыли (PnL) с учетом всех комиссий сетей.

---

**Правила работы:**
1. Мы двигаемся строго последовательно. Следующий шаг начинается только после полной отладки и тестирования предыдущего через симулятор.
2. Вся разработка ведется с соблюдением принципа Event-Driven Architecture (Feature-First) и обменивается данными через Event Bus.
