# 06_FULL_AUTO_CONCEPT.md (Концепт Полной Автоматизации)

**Статус:** `Implementation` - концепция находится в активной стадии реализации (внедрен Модуль Снайпера с использованием CDP-инъекций).
**Цель:** Переход от полуавтоматического сканера (открытие вкладок) к полностью автономному торговому боту (Full Auto) в условиях отсутствия или запрета публичного API целевой биржи (XT.com).

---

## 1. Фундаментальная проблема (Anti-Bot & Latency)
Попытка автоматизировать торговлю через веб-интерфейс биржи сталкивается с двумя главными врагами:
1. **Защита от ботов (Cloudflare, Behavioral Analysis):** Биржи активно блокируют нестандартное поведение, скриптовые клики (где `isTrusted = false`) и подозрительные заголовки браузера.
2. **Задержка (Latency):** Сигнал живет секунды. Любая автоматизация, требующая полной загрузки DOM-дерева тяжелой биржи, рискует купить монету, когда арбитражное окно уже закрылось (Slippage).

## 2. Сравнение подходов к автоматизации

### Вариант 1: Playwright / Puppeteer (Браузерная автоматизация)
* **Механика:** Поднятие headless/видимого браузера, поиск селекторов кнопок в DOM, отправка команд на клик.
* **Риск бана:** 🔴 **Высокий**. Оставляет явные следы (например, флаги `webdriver`). Биржи легко детектируют такие сессии.
* **Задержка:** 1000–3000 мс (самый медленный вариант из-за ожидания рендера).
* **Вердикт:** Не подходит для высокочастотного арбитража.

### Вариант 2: OS-Level GUI Automation (Эмуляция мыши ОС)
* **Механика:** Перехват управления физическим курсором ОС (библиотеки типа `robotjs`). Скрипт физически двигает мышь по координатам (x,y) и кликает.
* **Специфика реализации (Идея):** Чтобы избежать кликов "в молоко" из-за адаптивной верстки, биржа XT.com открывается не в новой вкладке, а в **новом окне с жестко зафиксированным размером** (например, 800x600) и позицией на экране.
* **Риск бана:** 🟢 **Очень низкий**. Браузер видит аппаратные прерывания операционной системы.
* **Задержка:** 1000–2500 мс.
* **Минусы:** В момент сделки отбирает мышь у пользователя. Требует калибровки координат.

### Вариант 3: Инъекция через CDP (Chrome DevTools Protocol) — 🏆 Золотая середина
* **Механика:** Использование уже имеющегося CDP-клиента. Подключение к открытой вкладке XT.com и отправка команд напрямую в движок Chrome (`Input.dispatchMouseEvent`, `Input.insertText`), минуя JavaScript страницы.
* **Риск бана:** 🟡 **Средний**. Требует генерации "человеческих" траекторий движения мыши (кривые Безье) и микро-задержек между нажатием и отпусканием кнопки, чтобы пройти Behavioral Analysis.
* **Задержка:** 500–1500 мс.

### Вариант 4: Реверс-инжиниринг приватного Web API
* **Механика:** Сниффинг HTTP POST запросов (покупка руками), копирование структуры запроса, заголовков и Cookie, отправка аналогичных запросов напрямую из Node.js.
* **Риск бана:** 🔴 **Критический**. Любая ошибка в генерации динамической подписи или анти-фрод токена ведет к моментальной заморозке аккаунта.
* **Задержка:** 50–100 мс (идеально быстро, без загрузки UI).

## 3. Решение ключевых технических проблем (CDP-подход)

### Проблема A: Свойство `isTrusted`
При обычном вызове `button.click()` из JS-консоли, браузер помечает событие флагом `Event.isTrusted = false`. Защита биржи это видит и игнорирует клик.
**Решение:** Команды CDP (`Input.dispatchMouseEvent`) исполняются на уровне движка C++. Сгенерированные таким образом события всегда имеют `isTrusted = true` и неотличимы от физической мыши. Главное — эмулировать естественную скорость перемещения курсора (предотвращение "телепортации" из точки 0,0).

### Проблема B: Актуальность стакана (Orderbook) и проскальзывание
Сигнал может устареть за те 1-2 секунды, пока открывается биржа. Покупать по "Market" ордеру опасно. Скрипт должен понимать текущую цену Ask.
**Решение (Browser as API):**
1. Открываем целевую страницу через CDP.
2. Подписываемся на вкладку XT.com и перехватываем **её собственный WebSocket-трафик** через тот же домен Network (как мы это делаем со сканером).
3. Парсим живой стакан в памяти Node.js (in-memory).
4. Сравниваем реальный спред с данными из сигнала.
5. Если профит еще есть — исполняем клик покупки (Limit ордер по цене Ask). Если цена ушла — скрипт закрывает вкладку/окно (Abort).

---

## 4. Архитектурный план на будущее
Если мы переходим к автоматизации, оптимальным вектором развития является гибрид: **Вариант 3 (CDP для кликов и чтения WebSocket стакана) + Идея из Варианта 2 (открытие нового окна с фиксированным Viewport через CDP для стабильности верстки)**. 
Это позволит сохранить безопасность депозита и обеспечит достаточную скорость реакции.
