# План ручного тестирования (QA MANUAL) - Этап 3

Этот план поможет тебе убедиться, что код, написанный по ADR-003, работает корректно и не ломает существующий функционал.

## Подготовка
1. Убедись, что запущен целевой браузер Chrome с флагом отладки (согласно Этапу 1: `--remote-debugging-port=48192 --user-data-dir="/tmp/chrome_dev_test"`).
2. Открой в этом браузере вкладку оригинального сканера (чтобы пошел трафик).
3. Для удобства тестирования временно установи в `config.ts`:
   * `CEX_FILTER_ENABLED: false` (чтобы ловить больше сигналов).
   * `ANTI_SPAM_TTL_MS: 30000` (30 секунд, чтобы не ждать целую минуту при проверке кэша).

## Тест-кейс 1: Инициализация и создание директорий
1. Запусти скрипт командой `npm start` (или `npx ts-node src/main.ts`).
2. **Ожидаемый результат:** В консоли должны появиться сообщения об успешном старте (например, `[Main] Starting XT Scanner Iteration 2`). Скрипт не должен упасть.
3. Открой корневую папку проекта в редакторе кода.
4. **Ожидаемый результат:** В корне должна автоматически появиться папка `logs/` (если её не было).

## Тест-кейс 2: Проверка Анти-спам фильтра (TTL)
1. Дождись появления любого первого сигнала в терминале.
   * *Пример вывода: `[🔥 СИГНАЛ] PYBOBO | MEXC -> JUP ...`*
2. Сразу после этого обрати внимание на работу сканера в браузере. Обычно он шлет дубли этого же тикера (PYBOBO) каждые 2-3 секунды.
3. **Ожидаемый результат (Спам отсечен):** В течение следующих 30 секунд (наш тестовый TTL) в терминале **НЕ ДОЛЖНЫ** появляться новые сообщения `[🔥 СИГНАЛ]` с этим же тикером `PYBOBO`. Консоль должна оставаться чистой (без спама). Сигналы с *другими* тикерами при этом должны проходить свободно.
4. Подожди более 30 секунд. Если арбитражное окно по `PYBOBO` все еще открыто и сигнал придет снова.
5. **Ожидаемый результат (Кэш сброшен):** Сообщение `[🔥 СИГНАЛ] PYBOBO ...` должно снова единоразово появиться в консоли.

## Тест-кейс 3: Проверка Логгера (Запись в файл)
1. Убедись, что в консоли промелькнуло несколько разных уникальных сигналов (которые прошли спам-фильтр).
2. Останови скрипт (`Ctrl+C`).
3. Открой файл `logs/signals_log.jsonl`.
4. **Ожидаемый результат:** * Файл должен существовать.
   * Внутри должно быть ровно столько строк, сколько уникальных сообщений `[🔥 СИГНАЛ]` ты увидел в консоли.
   * Каждая строка должна представлять собой валидный JSON-объект (структуры `ISignalPayload`). Проверить валидность можно скопировав одну строку в любой JSON-форматтер.
   * В файле **не должно быть** сотен одинаковых записей подряд, сгенерированных в одну и ту же секунду.

## Тест-кейс 4: Устойчивость при ошибках (Регрессия)
1. При работающем скрипте обнови страницу сканера в браузере (`F5` или `Cmd+R`).
2. **Ожидаемый результат:** Скрипт должен выбросить ошибку соединения, подождать 3 секунды и успешно переподключиться к новой сессии (как это было настроено в Этапе 2). Работа логгера и Event Bus при этом не должна сломаться.
